1. PIPELINE VALIDITY & COMPLETENESS (CURRENT MVP)
------------------------------------------------------------------------
The current pipeline successfully implements a lightweight, end-to-end unstructured data-to-insights engine. The 6-stage flow accurately reflects the existing codebase:

STAGE 1: Data Ingestion
- Multi-modal Python scrapers (Reddit, YouTube, Play Store, iOS) run daily via `daily_pipeline.bat`.
- Output: Raw unstructured JSON files stored locally.

STAGE 2: Preprocessing
- `cleaner.py` strips noise, drops invalid rows, and standardizes the text format.
- Output: Validated JSON files in the `data_cleaned` directory.

STAGE 3: Embedding & Indexing
- `embedder.py` generates dense vector embeddings using `all-MiniLM-L6-v2` (HuggingFace).
- Output: Deterministically indexed documents stored in a persistent local ChromaDB instance.

STAGE 4: Offline Classification & Tagging
- `classifier_agent.py` and `intent_agent.py` use Groq's `qwen3.8-27b` model to asynchronously process ChromaDB records, adding intent and category metadata.

STAGE 5: On-the-Fly Theme & Persona Aggregation
- The FastAPI backend (`main.py`) dynamically reads ChromaDB and assigns reviews into 5 macro-themes (e.g., "Sizing & Fit") and 5 distinct personas (e.g., "Quality Seeker") using a fast, rule-based keyword mapping system during data load.

STAGE 6: RAG Insights Generation & Dashboard
- When a PM searches for insights on the Next.js frontend, FastAPI triggers a Retrieval-Augmented Generation (RAG) chain. 
- It retrieves the top 5 most relevant documents from ChromaDB and synthesizes a structured answer using Groq's `qwen3.8-27b` model.

------------------------------------------------------------------------
2. CLUSTERING & DATA PROCESSING ARCHITECTURE
------------------------------------------------------------------------
* Rule-Based Macro-Themes vs. ML Clustering:
  The MVP currently utilizes a fast, deterministic keyword-bucketing function (`assign_theme`) to group reviews into 5 predefined macro-themes. This approach guarantees zero latency when rendering the dashboard and provides highly predictable, static charts for Product Managers, avoiding the unpredictability of unsupervised machine learning (like HDBSCAN) at this early stage.

* Metadata Handling:
  The MVP uses basic metadata (source and ID) to track data lineage. Offline AI agents progressively enrich this metadata with behavioral categories, allowing for flexible filtering in future iterations.

------------------------------------------------------------------------
3. LATENCY & PRODUCTION REALISM
------------------------------------------------------------------------
* Dashboard Load Time:
  By performing the heavy lifting offline (Scraping, Embedding, and LLM Classification) and keeping the macro-theme bucketing simple and rule-based, the dashboard's initial load time remains incredibly fast.

* Real-Time RAG Synthesis:
  The only real-time AI invocation occurs when a specific query is executed. Because it uses Groq's ultra-fast LPU inference infrastructure to run the `qwen3.8-27b` model, the RAG synthesis response times are minimized, offering a highly responsive interactive search experience for the PM without the need for complex pre-caching infrastructure.
